Case Study

Agentic Deep Research System

An autonomous multi-agent research pipeline — drop in a topic, get back a structured Markdown report. Four specialized agents collaborate over HTTP: a planner, an expert interviewer with live web search, a report writer, and a governing orchestrator that enforces quality requirements before each step completes.

View on GitHub

What it does

Given a research topic, the system:

  • Plans — generates a set of analyst personas (e.g. "Plasma Physicist at MIT", "Energy Policy Expert at Carnegie") tailored to the topic.
  • Interviews — runs each analyst through a ReAct loop, calling live web search (Tavily) and Wikipedia via MCP tools.
  • Writes — synthesizes all findings into a structured Markdown report with introduction, body, and conclusion.
  • Governs — a BeeAI orchestrator enforces a 4-step checklist and retries any step that produces insufficient output.

Architecture

Each agent runs as an independent ASGI server discoverable via /.well-known/agent.json (the A2A standard). The MCP tool server is spawned as a stdio subprocess by the interview agent — no extra port required.

How the orchestrator enforces quality

The BeeAI RequirementAgent runs a 4-step checklist on every iteration. A step only unlocks after the previous one passes — this prevents partial outputs from silently propagating through the pipeline.

StepCondition checkedAction if not met
1Analyst list existsThink → call PlannerTool
2Interview sections existThink → call InterviewTool with analyst JSON
3Final report existsThink → call WriterTool with sections JSON
4Report length > 200 charsRetry WriterTool

Design decisions worth noting

Why stdio MCP instead of HTTP MCP?

The expert agent spawns the MCP server as a subprocess via MultiServerMCPClient + StdioConnection. This avoids managing an extra HTTP port and keeps the tool server tightly scoped to the agent that needs it.

Why lazy async init on the expert agent?

MCP client initialization (MultiServerMCPClient.__aenter__) must happen inside an async context. The initialize() pattern separates object construction (sync) from tool discovery (async), making the agent safe to instantiate at import time.

Why structured Pydantic outputs everywhere?

Every LLM call uses llm.with_structured_output(Model). This eliminates JSON parsing errors at agent boundaries and gives full type safety across the pipeline — the orchestrator never receives a malformed payload.

Why BeeAI for orchestration instead of another LangGraph graph?

BeeAI's RequirementAgent provides declarative quality gates (ConditionalRequirement) without writing custom routing logic. The orchestrator's job is governance, not research — keeping those concerns separate makes each layer easier to test and replace.

Local mode

The full pipeline also runs in a single process without spinning up four servers, which is the recommended way to explore the system (used by the project's notebook): 

from langchain_groq import ChatGroq
from research_system import ResearchGraph

llm = ChatGroq(model="llama-3.3-70b-versatile")
graph = await ResearchGraph(llm).initialize()
report = await graph.run("The future of fusion energy")
print(report)
