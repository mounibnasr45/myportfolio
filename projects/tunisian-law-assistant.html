Agent Juridique Tunisien
Tunisian Legal AI Assistant

A citation-grounded retrieval-augmented legal assistant for Tunisian law — the Constitution, the Penal Code, and the decree-law on press freedom — that grounds every answer in specific, cited articles rather than the model's own training data.

FastAPI LangGraph PostgreSQL + pgvector Angular 22 Hybrid RAG
Live Demo View on GitHub

Overview

Agent Juridique Tunisien answers legal questions in French or English against three indexed source texts, and grounds every answer in specific, cited articles rather than the model's own memory. It is built as a small production service rather than a notebook: typed configuration, a migrated relational schema, an authenticated multi-tenant API, a retrieval pipeline measured against a hand-built golden set, and a CI pipeline that gates deploys on that measurement rather than on vibes.

Design thesis

An LLM-based legal assistant is worthless — or dangerous — the moment it cannot prove where an answer came from, or fails silently instead of loudly. Every architectural boundary in this codebase defends that thesis: a citation is a foreign-key row (citations.chunk_id → chunks.id), not a string the model was asked nicely to produce.

System architecture

The default deployment is two Render web services — an nginx-served Angular bundle proxying /api to a separate FastAPI container — which decouples the UI's release cycle from the API's. The same API service can also serve the built SPA itself from one process, which is what powers the single-container deployment used for the live demo above.

The codebase is a textbook Ports & Adapters (hexagonal) architecture, enforced by import direction rather than convention alone — app/domain/ physically cannot import SQLAlchemy, LangChain, or FastAPI. That is what makes the domain layer testable with in-memory fakes, and what lets an offline ablation harness sweep 11 retrieval configurations against a real corpus while tests/test_fusion.py exercises the exact same math with zero I/O.

Retrieval-augmented generation

Article-aware chunking

Legal text is split on article boundaries, not by a fixed character count. A fixed-size splitter cuts through the middle of articles, which makes a citation meaningless — "according to article 258" has to point at the whole article, not a fragment of it.

Hybrid retrieval

Every search runs two arms and fuses their results:

  • Dense — cosine distance between the query embedding and every chunk's stored embedding, via pgvector.
  • Lexical — Postgres full-text search (ts_rank_cd against a french_unaccent configuration), not an in-memory index, so it survives a process restart.

The two candidate sets are combined either by weighted score or reciprocal rank fusion, selectable per query. Measured against the golden set below, dense retrieval alone outperforms every hybrid weighting on this corpus, so HYBRID_WEIGHT_BM25=0.0 is the shipped default — the lexical arm stays fully implemented and part of the ablation sweep, because that result is a property of this corpus, not a law of retrieval.

Agent topology

The reasoning loop is a LangGraph create_react_agent: native tool-calling, not a text-parsed ReAct template, so there is no output format for the model to imitate incorrectly. It has exactly one tool, rechercher_textes_juridiques, and a hard cap of four iterations — a runaway agent doing ten searches for one question is the single largest latency and cost sink an unbounded loop can produce.

The reflection checkpoint runs once, after the loop produces a draft, entirely outside the graph. It asks a second, tool-less LLM call whether the draft leans on a legal term of art the retrieved articles never defined — a term like préméditation can appear in one article while being defined in another the first search never surfaced. Anything that fails (empty reply, timeout, malformed response) fails open and returns the original draft untouched.

Tracing

Every retrieval call and every reflection pass is recorded into an AgentTrace — what was searched, what came back and at what rank, whether a reflection pass found a gap. The trace is not a debug log: it is returned to the client and rendered as the visible reasoning path in the Angular UI, so a user can see which query the agent actually issued and which articles it read before answering.

A citation row can only exist if chunk_id names a chunk the retrieval tool actually returned — the foreign key makes a fabricated citation a schema violation, not a prompting hope. Conversation state exists in two places on purpose: LangGraph's checkpointer owns an opaque, versioned blob whose only job is resuming execution, while conversations/messages/citations is a separate, queryable read model built for the product — coupling "list my chats" to a library's internal serialization format is one LangGraph upgrade away from breaking.

Evaluation

Retrieval quality is measured, not assumed. A 56-question hand-written golden set, each mapped to the one article that answers it, is swept across every retrieval configuration and gated in CI — a deploy fails if any arm's hit@5 regresses by more than three points against a committed baseline.

Challenges & solutions

A silent 12% of the corpus was never searchable

The original embedding model accepted 128 tokens while chunks were sized in characters — roughly 200–250 tokens for French legal prose — so it silently truncated over a third of penal-code chunks before embedding them, with no error, only a library warning nobody was watching. It was found by building the evaluation harness, not by any exception: hit@1 moved from 0.250 to 0.679 on the same corpus, same questions, purely from switching to an encoder with a 512-token context. That is the reason the evaluation harness exists as a permanent CI gate rather than a one-off script.

A free-tier host with less memory than the model needed

The service targets hosting with no ongoing cost, capping memory at 512MB. A local embedding encoder — even after removing every non-essential dependency — still peaked at just over 500MB resident. The embedding step moved out of the process entirely to an API call, which is also what motivated writing the embeddings layer against a provider-agnostic Embedder protocol from the start: the local encoder still exists and is a straight environment-variable switch away on a host with more headroom.

Retrieval had to survive a cold process

An earlier design cached the lexical index in process memory; it worked in every manual test and returned dense-only results with no warning after any restart, because the in-memory index was simply gone. The fix — a generated tsvector column, indexed and queried in the same statement as everything else — removed that entire class of bug structurally.
