Medical Agentic System

An enterprise-grade AI medical assistant combining multi-agent orchestration, GraphRAG (graph + vector retrieval), and conversational memory to deliver context-aware, evidence-grounded clinical decision support — drug interactions, contraindications, and treatment guidance.

CrewAI Neo4j + Graphiti FastAPI LangChain Memory Groq Llama 3.3

Overview

The system routes each incoming question through an LLM-powered router that scores intent and complexity, then dynamically allocates 1–3 specialized CrewAI agents — a clinical researcher, a safety validator, and a clinical analyst — to answer it. Every session keeps conversational memory so follow-up questions ("what are its interactions?") resolve against the drug named earlier in the conversation.

Intelligent query router

A Groq Llama-3.3-70B call analyzes every query and returns a validated Pydantic QueryAnalysis — intent, a 1–5 complexity score, which agents to spin up, per-agent iteration budgets, and a rejection path for non-medical queries. Nothing downstream trusts free-text classification; the router's output is a typed contract. 

QueryAnalysis(
    intent="drug_interaction",
    complexity=3,
    required_agents=["researcher", "validator", "analyst"],
    max_iterations={"researcher": 4, "validator": 2, "analyst": 2},
    suggested_tools=["graph_db", "web_search"],
    is_medical=True,
    confidence=0.95,
    reasoning="Complex drug interaction requires multi-agent validation"
)

GraphRAG knowledge system

Medical entities and relationships live in Neo4j; Graphiti layers hybrid vector + graph search on top, using all-MiniLM-L6-v2 embeddings for semantic matching alongside graph traversal. A DuckDuckGo web-search tool is the fallback whenever the graph has no answer, and a direct Cypher-query tool handles complex pattern matching the hybrid search doesn't cover.

Conversation memory

Each session gets an isolated LangChain ConversationBufferMemory, summarized automatically once a conversation passes ten messages. Memory is in-process (no disk I/O), so context injection into a follow-up query is effectively free.

Performance optimizations

  • Multi-level caching — MD5-hashed response cache (1-hour TTL) plus a separate tool-level cache for graph DB and web-search results.
  • Lazy loading — the Neo4j driver, the Graphiti client, and the embeddings model are all initialized on first use, not at startup.
  • Streaming — Server-Sent Events expose the agents' live reasoning ("recherche en cours…") instead of a blank wait.
  • Tool diversity enforcement — agents are prompted to switch tools between iterations rather than repeating a query that already returned nothing useful.

Processing mode selection

Two execution modes share the same router output: Crew mode (sequential, CrewAI task delegation) for most queries, and MCP mode (parallel tool execution) auto-selected when complexity ≥ 3, the intent is an interaction check, and multiple tools are needed at once — with a manual use_mcp override available on the API.
